# Runtime Assets

Large runtime binaries are deliberately excluded from ordinary Git history.

The source repository ignores:

```text
src/main/java/chess/stockfish/stockfish.exe
src/main/resources/tablebases/
tablebases/
tablebase-test-output/
```

This keeps the source repository small and prevents large generated assets from becoming permanent Git objects.

## Stockfish

Stockfish is optional. It is used as a reference engine, not as part of the native Dovetail/Hybrid search.

The v1.0 integration was verified with **Stockfish 18**.

Official download:

https://stockfishchess.org/download/

Official source/release repository:

https://github.com/official-stockfish/Stockfish

Stockfish 18 release tag:

```text
sf_18
```

### Configuration

The client checks the JVM property:

```text
stockfish.path
```

and environment variable:

```text
STOCKFISH_PATH
```

before trying common local locations.

Example:

```powershell
$env:STOCKFISH_PATH="C:\Tools\stockfish\stockfish-windows-x86-64-avx2.exe"
java -jar target\chess-engine-1.0.0.jar
```

or:

```powershell
java "-Dstockfish.path=C:\Tools\stockfish\stockfish-windows-x86-64-avx2.exe" -jar target\chess-engine-1.0.0.jar
```

The client also recognizes common extracted Stockfish executable naming patterns rather than requiring the file to be renamed to `stockfish.exe`.

## Tablebases

Exact tablebase binaries are generated by this project but are excluded from Git because several assets are large.

During development, the project uses generated assets beneath locations including:

```text
src/main/resources/tablebases/
tablebases/four-piece/
```

The v1.0 release packaging phase will distribute the required tablebase assets separately from the source repository.

The source code retains the builders, codecs, runtime services, validation programs, and release gates used to generate and verify those assets.

## Clean Source Clone

A clean source clone can compile and launch the GUI without committing the local Stockfish executable or generated tablebase files.

Features that require external runtime assets should be tested after those assets are installed:

- Stockfish comparison/continuations require a Stockfish executable.
- Exact tablebase modes require the corresponding generated tablebase assets.

The formal release package should keep source, third-party executables, and generated tablebase data as distinct artifacts.
