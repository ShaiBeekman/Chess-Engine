# Runtime Assets

Large runtime binaries are deliberately excluded from ordinary Git history.

The source repository ignores:

```text
src/main/java/chess/stockfish/stockfish.exe
src/main/resources/tablebases/
tablebases/
tablebase-test-output/
```

This keeps the source repository small and prevents large generated assets from becoming permanent Git objects.

## Stockfish

Stockfish is optional. It is used as a reference engine, not as part of the native Dovetail/Hybrid search.

The v1.0 integration was verified with **Stockfish 18**.

Official download:

https://stockfishchess.org/download/

Official source/release repository:

https://github.com/official-stockfish/Stockfish

Stockfish 18 release tag:

```text
sf_18
```

### Configuration

The client checks the JVM property:

```text
stockfish.path
```

and environment variable:

```text
STOCKFISH_PATH
```

before trying common local locations.

Example:

```powershell
$env:STOCKFISH_PATH="C:\Tools\stockfish\stockfish-windows-x86-64-avx2.exe"
java -jar Chess-Engine-v1.0.2.jar
```

or:

```powershell
java "-Dstockfish.path=C:\Tools\stockfish\stockfish-windows-x86-64-avx2.exe" -jar target\chess-engine-1.0.2.jar
```

The client also recognizes common extracted Stockfish executable naming patterns rather than requiring the file to be renamed to `stockfish.exe`.

## Tablebases

Exact tablebase binaries are generated by this project but are excluded from Git because several assets are large.

### Windows application image (local preparation)

Build with `package-windows.ps1` using JDK 26 and the verified original
`Chess-Engine-v1.0.0-tablebases.zip` listed below. Maven builds the source cleanly;
`jdeps` determines the module roots, `jlink` supplies Java, and `jpackage` creates
`Chess Engine.exe` with the official ICO embedded. No compiler is needed at runtime.

Extract the whole new Windows ZIP and double-click **Chess Engine.exe**:

```text
Chess Engine/
  Chess Engine.exe
  app/                    internal JAR, launcher configuration, module list
  runtime/                bundled Java and its legal notices
  tablebases/             6 three-piece assets
    four-piece/           30 canonical four-piece assets
  stockfish/              optional executable and instructions
  LICENSE
  README.txt
```

Do not move the EXE alone. Users do not need Java or Maven installed separately.
There is no loose top-level ICO: the executable embeds it and the JAR embeds the PNG.

The launcher sets `user.dir` to `$APPDIR/..` using jpackage's runtime macro,
so existing NIO-based tablebase and Stockfish paths resolve against the extracted
image even when launched from another working directory. No developer path is
embedded. Existing APPDATA/user-home progress storage remains unchanged.
Stockfish remains optional; explicit property/environment configuration retains
its precedence. Put an extracted Stockfish executable in the adjacent stockfish
folder for automatic discovery without environment changes.

The app image and ZIP are generated under `target/`; existing published v1.0.2
release assets and tags are unchanged. Historical JAR packages still require Java
26 separately. Generated tablebases remain external to the application JAR and
are copied unchanged from the original verified archive, not rebuilt.

### Local app-image verification

The clean Maven build and jpackage image build passed. The bundled Java 26 runtime
contains `java.base`, `java.desktop`, `java.datatransfer`, `java.prefs`, and `java.xml`.
Its root modules were determined by `jdeps`; the remaining modules are dependencies.
See the [JDK 26 jpackage documentation](https://docs.oracle.com/en/java/javase/26/docs/specs/man/jpackage.html).

Verified locally on Windows:

- Direct `Chess Engine.exe` launch from an unrelated directory with Java removed
  from PATH and JAVA_HOME cleared; the process loaded its own
  `runtime/bin/server/jvm.dll`, showed the blue/teal window icon, and exited with code 0.
- All seven embedded native EXE icon frames match the source ICO byte-for-byte.
- The packaged PNG matches the master; the primary Swing window receives it.
- Core regression, three-piece resource loading, and unified four-piece study
  routing pass using the bundled runtime and the launcher's asset-root setting.
- The 128 MiB KPKP child check passes for persisted identity and ordinary/en-passant
  service and exact-facade routing using the same packaged asset-root setting.
- Optional Stockfish 18 is discovered in the image's stockfish folder, and its
  forced-mate smoke check passes without an explicit Stockfish path. The temporary
  executable was removed afterward and is not included in the ZIP.
- All 36 tablebases match the verified original archive. ZIP CRCs pass. No
  development-machine paths, source/IDE/test output, or loose top-level ICO/JAR
  are present in the distribution.

The native GUI and ordinary verification JVMs used a temporary 256 MiB heap cap
because this host is memory constrained; the KPKP child used 128 MiB. These limits
are not written into the package. The M86 wrapper does not propagate `user.dir`
to its own child, so testing its child from a foreign working directory requires
passing the packaged asset-root option explicitly (or running the wrapper from
the image root). No production Java code was changed for this packaging.

This is a local app-image test, not a fresh Windows VM or consumer SmartScreen
certification. The EXE is unsigned; Windows icon caches and pinned shortcuts may
retain older icons. Preserve the full extracted folder. Published releases and
tags have not been changed.

## Clean Source Clone

A clean source clone can compile and launch the GUI without committing the local Stockfish executable or generated tablebase files.

Features that require external runtime assets should be tested after those assets are installed:

- Stockfish comparison/continuations require a Stockfish executable.
- Exact tablebase modes require the corresponding generated tablebase assets.

The formal release package should keep source, third-party executables, and generated tablebase data as distinct artifacts.
