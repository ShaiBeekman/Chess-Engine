# Endgame composition pass - 2026-09-06

This pass preserves the established Endgame visual language and reallocates space
from study/mastery to the committed move path. The saved pre-pass sources and
large dark image are in `target/endgame-composition/before/`.

## Composition

At the existing 1920 x 1080 monitor simulation (native insets and 40px taskbar
allowance), the upper cards shrink from 569px to 247px. The review card grows from
68px to 390px. Current Study places side-to-move and exact proof together and
integrates Tablebase Defense into the proof/status block. Mastery uses three
adjacent counters, a shared order/reset row, the original mastery fraction/bar,
and the original position cursor. Large counter text stacks when it cannot fit.

Review shows START, connected committed moves, SAN, the mover, OPTIMAL, and
available exact result/DTM transitions. The selected move uses the existing blue
accent. Previous/Next Move share the review header, preserving room for a complete
selected move row even at 1280 x 720; the unchanged bottom
Hint / Give Up / Next Position actions remain fixed outside the scrolling body.

## Data and behavior boundaries

Only committed `gameHistory` positions are passed to the presentation component.
It never requests best moves, a principal variation, or a future continuation.
The current Curriculum loop accepts only exact-best player moves and exact
opponent replies; rejected attempts are restored and never enter history. Thus
OPTIMAL is truthful for this path, while INACCURATE and WIN -> DRAW are not
fabricated for discarded attempts. Missing tablebase information leaves exact
telemetry absent. Results use the initial trainee's side consistently, and DTM
uses the tablebase's raw ply distances. Snapshots are retained across material
changes; old positions are not probed again during review navigation.

ChessWindow has only two additional presentation snapshot calls. Its existing
window state, move acceptance, defense, navigation, callbacks, and progress logic
are unchanged. Engine/tablebase/progress/controller code and board layout were
not edited. The footer and listener wiring match the saved source exactly. The
shared Body layout uses an opt-in flag, preserving Solver's existing allocation.

## Verification

Results and final captures are recorded under `target/endgame-composition/`.
The layout gate now uses a legal KQK history generated by the existing exact
best-move API solely in the test fixture. It checks composition and confirms SAN,
DTM, result perspective, no future moves, reset behavior, and absent proof data.
The live interaction gate additionally checks committed path length, previous /
next review navigation, unchanged history, restored board input, and clearing the
path on Next Position. All live study tests use an isolated APPDATA directory.

Windows memory pressure required a 16MiB initial verification JVM heap (512MiB
maximum). Maven packaging used a 256MiB heap, Serial GC, and
`-XX:TieredStopAtLevel=1` to reduce compiler native memory. These are process-local
options; no system settings, user applications, or verification assertions changed.
The final screenshots refresh the original `target/endgame-redesign/layout/` and
`layout-scale125/` paths as well as the dedicated composition artifact directory.
