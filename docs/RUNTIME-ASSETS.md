# Runtime Assets

Large runtime binaries are deliberately excluded from ordinary Git history.

The source repository ignores:

```text
src/main/java/chess/stockfish/stockfish.exe
src/main/resources/tablebases/
tablebases/
tablebase-test-output/
```

This keeps the source repository small and prevents large generated assets from becoming permanent Git objects.

## Stockfish

Stockfish is optional. It is used as a reference engine, not as part of the native Dovetail/Hybrid search.

The v1.0 integration was verified with **Stockfish 18**.

Official download:

https://stockfishchess.org/download/

Official source/release repository:

https://github.com/official-stockfish/Stockfish

Stockfish 18 release tag:

```text
sf_18
```

### Configuration

The client checks the JVM property:

```text
stockfish.path
```

and environment variable:

```text
STOCKFISH_PATH
```

before trying common local locations.

Example:

```powershell
$env:STOCKFISH_PATH="C:\Tools\stockfish\stockfish-windows-x86-64-avx2.exe"
java -jar Chess-Engine-v1.0.1.jar
```

or:

```powershell
java "-Dstockfish.path=C:\Tools\stockfish\stockfish-windows-x86-64-avx2.exe" -jar target\chess-engine-1.0.1.jar
```

The client also recognizes common extracted Stockfish executable naming patterns rather than requiring the file to be renamed to `stockfish.exe`.

## Tablebases

Exact tablebase binaries are generated by this project but are excluded from Git because several assets are large.

### v1.0.1 release asset

The complete Windows package is `Chess-Engine-v1.0.1.zip`. Extract the whole
archive and run `java -jar Chess-Engine-v1.0.1.jar` with Java 26 installed.
Keep the adjacent `tablebases/` and optional `stockfish/` directories. The official
window logo is loaded from inside the JAR; `chess-engine-logo.ico` is included
for Windows shortcuts. No separate image installation is needed.

For users downloading the standalone JAR, the unchanged exact endgame data is
also distributed separately as:

```text
Chess-Engine-v1.0.1-tablebases.zip
```

Extract the ZIP into the same directory as `Chess-Engine-v1.0.1.jar`. The archive already contains the required top-level `tablebases` directory.

The resulting runtime layout is:

```text
Chess-Engine-v1.0.1.jar
tablebases/
├── KPK-black-v1.tb
├── KPK-white-v1.tb
├── KQK-black-v1.tb
├── KQK-white-v1.tb
├── KRK-black-v1.tb
├── KRK-white-v1.tb
└── four-piece/
    ├── KQQK-white.ftb.gz
    ├── KQRK-white.ftb.gz
    ├── ...
    └── KP-KP-canonical-ep.ftb.gz
```

The v1.0.1 bundle contains:

```text
6 three-piece .tb assets
30 canonical four-piece .ftb.gz assets
```

Three-piece runtime loading checks the external `tablebases/` directory before packaged/development resources. Four-piece runtime data uses `tablebases/four-piece/`.

The older uncompressed development-only `KQRK-*-v1.tb` files are not part of the v1.0.1 release bundle; KQRK runtime coverage is supplied by the canonical compressed `four-piece/KQRK-white.ftb.gz` asset.

During development, generated assets may also exist beneath:

```text
src/main/resources/tablebases/
tablebases/four-piece/
```

The source code retains the builders, codecs, runtime services, validation programs, and release gates used to generate and verify those assets.

## Clean Source Clone

A clean source clone can compile and launch the GUI without committing the local Stockfish executable or generated tablebase files.

Features that require external runtime assets should be tested after those assets are installed:

- Stockfish comparison/continuations require a Stockfish executable.
- Exact tablebase modes require the corresponding generated tablebase assets.

The formal release package should keep source, third-party executables, and generated tablebase data as distinct artifacts.
